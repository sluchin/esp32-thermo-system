# rtc_pcf8563.c の解析

対象: `app/thermo-node/drivers/rtc_pcf8563.c` (276 行)

拡張ボードの RTC (PCF8563、I2C のアドレス 0x51) のドライバです。Zephyr の RTC API の `set_time` と `get_time` だけを実装します。アラーム、更新のコールバック、校正は、実装しません。

## なぜ自前のドライバか

Zephyr v4.3 の RTC ドライバ (`nxp,pcf8563`) は、月と年の扱いが、チップと合っていません。

- 月: `rtc_time` の `tm_mon` は 0 から 11 ですが、チップの月のレジスタは 1 から 12 です。Zephyr のドライバは、検証では 0 から 11 を見ているのに、レジスタには、そのまま書きます。そのため、12 月が通りません。
- 年: `tm_year` は 1900 年からの年数 (2026 年なら 126) ですが、チップの年のレジスタは 00 から 99 です。Zephyr のドライバは、1900 年からの年数を、そのまま BCD にします。

このドライバは、`rtc_time` の値を、チップのレジスタの値に正しく直します。そのため、compatible は `thermo,pcf8563` にしています (`nxp,pcf8563` は、Zephyr のドライバと重なるため)。バインディングは `dts/bindings/rtc/thermo,pcf8563.yaml`、Devicetree のノードは `boards/xiao_esp32c3.overlay` の `pcf8563@51` (alias `thermo-rtc`) です。

## レジスタ

| アドレス | 内容 | このドライバでの扱い |
|:---|:---|:---|
| 0x00 | 制御レジスタ 1 | 設定のとき 0 を書く (STOP ビットを下ろして、時計を動かす) |
| 0x02 | 秒 (bit 7 が VL: 電圧低下) | VL が 1 なら、時刻が信用できない |
| 0x03 | 分 | |
| 0x04 | 時 | |
| 0x05 | 日 | |
| 0x06 | 曜日 (0 から 6、日曜日が 0) | 範囲外なら -1 |
| 0x07 | 月 (bit 7 は世紀) | 下位 5 ビットだけを使う。世紀のビットは無視する |
| 0x08 | 年 (00 から 99) | 2000 を足す |

秒から年までの 7 バイトは、連続しているので、1 回の I2C の転送 (`i2c_burst_read_dt()`、`i2c_burst_write_dt()`) で読み書きします。秒が繰り上がる瞬間に、値がばらばらに読めてしまうことを避けられます。

値は BCD です。`bcd2bin()`、`bin2bcd()` (Zephyr の `sys/util.h`) で変換します。各レジスタの有効なビットは、マスク (`PCF8563_MASK_*`) で取り出します。

## pcf8563_set_time

```text
範囲の確認 (どれかが外れたら -EINVAL):
    秒 0〜59、分 0〜59、時 0〜23、日 1〜31、月 0〜11 (tm_mon)、年 100〜199 (tm_year)、曜日 0〜6
raw[] を BCD で作る:
    月 = tm_mon + 1、年 = tm_year - 100
制御レジスタ 1 に 0 を書く                   → 失敗したら返る
レジスタ 0x02 から 7 バイトを一括で書く       → 失敗したら返る
```

- 年の範囲は 100 から 199 (2000 年から 2099 年) だけです。世紀のビットは、書くときは 0 です。
- 秒のレジスタを書くと、VL ビットが 0 になります (時刻が有効になります)。
- 日の範囲は 1 から 31 までで、月ごとの日数 (30 日、2 月の 28 日と 29 日) は、確認しません。呼び出し側 (`node_time_set()`) が、実在する日付から作るので、問題になりません。

## pcf8563_get_time

```text
7 バイトを一括で読む                        → 失敗したら返る
秒の bit 7 (VL) が 1 なら                   → -ENODATA (時刻が未設定、または電池が切れた)
各レジスタをマスクして BCD から変換:
    月 = BCD - 1、年 = 100 + BCD
範囲外の値があれば                          → 警告を出して -ENODATA
曜日: 0〜6 ならそのまま。範囲外は -1
tm_yday = -1、tm_isdst = -1、tm_nsec = 0
```

範囲の確認は、BCD として不正なビットが立っているなど、チップの値が壊れているときの防御です。

## pcf8563_init

I2C のバスが使えるか (`i2c_is_ready_dt()`) だけを確かめます。RTC との通信は、しません (つながっているかは、時刻を読むときに分かります)。使えなければ `-ENODEV`。初期化の優先度は、`POST_KERNEL` と `CONFIG_RTC_INIT_PRIORITY` です。

## 定義の仕組み

`DT_INST_FOREACH_STATUS_OKAY(PCF8563_INIT)` が、Devicetree の `thermo,pcf8563` のノードごとに、設定 (`struct pcf8563_config`。I2C のバスとアドレス) と、デバイスを定義します (`DEVICE_DT_INST_DEFINE()`)。

`DEVICE_DT_INST_DEFINE()` は、Zephyr のマクロで、柔軟配列メンバー (`nodelabels`) を初期化します。このアプリのコードではなく、マクロの展開なので、`-Wpedantic` の警告を、そこだけ `#pragma GCC diagnostic` で止めています (理由は、コメントにあります)。

## 気づいた点

- 未使用のドライバ API (アラームなど) は、`DEVICE_API(rtc, ...)` に入れていません。`rtc_alarm_*()` を呼ぶと、`-ENOSYS` になります。
- `is_in_range()` は、`node_time.c` と `oled.c` にも、同じ形のものがあります。各ファイルが `static` で持っています。
- 時刻の読み出しと設定の間に、排他制御はありません。呼び出しは、メインスレッドと、BLE のスレッド (`write_time()`) の 2 つです。
