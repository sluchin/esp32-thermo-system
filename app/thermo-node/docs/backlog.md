# backlog.c の解析

対象: `app/thermo-node/src/backlog.c` (626 行) と `backlog.h` (156 行)

測定値の記録を SD カードに保存するコードです。1 つのファイル `backlog.bin` を、一定の件数の **輪 (リング)** として使い、記録ごとに「送信済み」のフラグを持ちます。ゲートウェイにも WiFi にもつながらなかった間の測定値を溜めておき、つながったときに古い順に送るために使います (ストア・アンド・フォワード)。呼び出し元は `direct.c` です。グラフの履歴の復元 (`history_store.c`) も、この記録を読みます。

ファイルの形式と、PC やシリアルでの読み方は、[../../../docs/sd_log.md](../../../docs/sd_log.md) にまとめてあります。この文書では、実装の動きを説明します。

## 公開する関数 (backlog.h)

| 関数 | 役割 |
|:---|:---|
| `backlog_mount()` | SD カードをマウントして、ログの保存を始める |
| `backlog_init()` | SD カードをマウントし、ファイルを走査して、状態を求める |
| `backlog_append()` | 測定値を 1 件保存する |
| `backlog_pending()` | 未送信の記録の数 |
| `backlog_read()` | 未送信の記録のうち、古い方から数えて `index` 番目を読む |
| `backlog_commit()` | 古い方から `n` 件を送信済みにする |
| `backlog_foreach_since()` | 指定の時刻以降の記録を、古い順に関数へ渡す |

`CONFIG_THERMO_BACKLOG=n` のときは、`backlog.c` はビルドされず、ヘッダのインライン関数が代わりになります (`backlog_init()` などは `-ENODEV`、`backlog_pending()` は 0 を返す)。呼び出し側は、SD カードがないときと同じに扱います。

## 記録の形式 (16 バイト、リトルエンディアン)

| 位置 | 大きさ | 内容 | 定数 |
|:---|:---|:---|:---|
| 0 から 3 | 4 | 測った UNIX 時刻 [s] (`uint32_t`) | `OFF_UNIX` |
| 4 から 5 | 2 | 温度 (`int16_t`、℃ の 10 倍) | `OFF_TEMP` |
| 6 から 7 | 2 | 湿度 (`uint16_t`、% の 10 倍。0xFFFF は湿度なし) | `OFF_HUMI` |
| 8 | 1 | 送信済みフラグ (0: 未送信、1: 送信済み) | `OFF_FLAG` |
| 9 から 10 | 2 | 気圧 (`uint16_t`、hPa の 10 倍。0 は気圧なし) | `OFF_PRES` |
| 11 | 1 | 予約 (0) | `OFF_RSVD` |
| 12 から 15 | 4 | 0 から 7 バイト目と、気圧の 2 バイトの CRC-32 | `OFF_CRC` |

- CRC は `record_crc()` が求めます。`crc32_ieee()` で 0 から 7 バイト目 (`CRC_RANGE` = 8) にかけ、気圧があれば (0 でなければ)、`crc32_ieee_update()` で気圧の 2 バイトを続けます。**フラグ (8 バイト目) は含めません。** そのため、送信が済んだときに 1 バイトだけを書き換えても、CRC を計算し直さずに済みます。
- **気圧を足す前の記録も、そのまま読めます**。以前の記録は、9 から 11 バイト目が予約 (0) で、CRC は 0 から 7 バイト目だけです。気圧が 0 の記録では、CRC を 0 から 7 バイト目だけにかけるので、以前の記録と同じ形になります。ファイルの中の気圧なしを 0 にしたのは、このためです。`struct backlog_record` の気圧なしは、ほかと同じ `THERMO_PRESSURE_NONE` (0xFFFF) で、`encode()` と `decode()` が置き換えます。0 hPa は測れない値なので、区別しなくて済みます。
- `decode()` は、CRC が合わない記録を無効にします。無効な記録は読み飛ばします。
- `encode()` は、予約の 1 バイトを 0 にして、CRC を末尾に付けます。

## 状態

| 変数 | 意味 |
|:---|:---|
| `count` | ファイルにある記録の数 (`BACKLOG_MAX_RECORDS` まで) |
| `head` | 次に書く物理の位置。輪が満杯でなければ `count` と同じ。満杯なら、最も古い記録の位置 |
| `pending` | 未送信の記録の数 |
| `first_pos` | 最も古い未送信の記録の論理の位置 (これより前は、全て送信済み)。`pending` が 0 のときは使わない |
| `is_mounted` | マウント済みか |

### 物理の位置と論理の位置

| 呼び方 | 意味 |
|:---|:---|
| 物理の位置 | ファイルの中の順番 (0 から `count - 1`)。バイトの位置は、`物理の位置 × 16` |
| 論理の位置 | 古い順の番号 (0 が最も古い) |

```c
static unsigned int physical(unsigned int pos)
{
    const unsigned int oldest = ((count >= BACKLOG_MAX_RECORDS) ? head : 0U);
    return (oldest + pos) % count;
}
```

輪が満杯になるまでは、2 つの位置は同じです。満杯になってからは `head` が最も古い記録なので、論理の位置 0 は物理の位置 `head` です。

## 輪の動き (例)

上限を 4 件として、`s` を送信済み、`u` を未送信とします。

| 操作 | ファイルの中身 (物理の位置 0 から 3) | head | 論理の順 (古い → 新しい) | pending | first_pos |
|:---|:---|:---|:---|:---|:---|
| A(s) B(s) C(u) D(u) を追記 | A B C D | 0 | A B C D | 2 | 2 |
| E(u) を追記 (A を上書き) | E B C D | 1 | B C D E | 3 | 1 |
| F(s) を追記 (B を上書き) | E F C D | 2 | C D E F | 3 | 0 |
| G(s) を追記 (C を上書き。C は未送信) | E F G D | 3 | D E F G | 2 | 0 |

満杯のあとは、論理の位置が 1 つずつ前にずれるので、`first_pos` も 1 つ減ります (0 未満にはしません)。未送信の記録が上書きされたときは、`pending` も 1 減ります。**送信済みの記録を選んで消す処理はなく**、常に最も古い位置を上書きします。未送信が上限より多く溜まらない限り、最も古い記録は、たいてい送信済みです。

## backlog_mount

SD カードの FatFS を `CONFIG_THERMO_BACKLOG_MOUNT` (`/SD:`) にマウントします。マウント済みなら、何もせずに成功を返します。失敗したら `-ENODEV` を返します。マウントできたら `sdlog_start()` を呼び、以降は `boot.log` と `error.log` が書かれます。記録の走査より速い (約 0.5 秒) ので、`main()` は、起動のログが RAM のバッファからあふれないように、起動の早い時点でこれを呼びます。

## backlog_init

1. 状態 (`count`、`head`、`pending`、`first_pos`) を 0 に戻します。呼び直すと、調べ直します。
2. `backlog_mount()` でマウントします (マウント済みなら、そのまま)。失敗したら `-ENODEV` を返します。
3. `fs_stat()` でファイルの大きさを調べ、`min(大きさ / 16, 上限)` を記録の数とします。ファイルがなければ 0 です。
4. `scan()` で全ての記録を読んで、状態を求めます。
5. ログに `SD card ready: N records, M not sent (mount ... ms, scan ... ms, uptime ... ms)` を出します。

### scan

記録を、ファイルの先頭から順に 1 件ずつ読みます。

- 読んだ件数を `count` にします。16 バイトに満たない端 (書きかけ) は読めないので数えず、次の追記で上書きします。
- CRC が合わない記録は、件数には数えますが、以降の判定には使いません。
- 最も新しい記録 (時刻が最大。同じときは後ろの方) の物理の位置を、`newest_phys` として覚えます。
- 未送信の記録の数を `pending` として数え、時刻が最も小さい未送信の記録の位置を `unsent_phys` として覚えます。

走査のあと、`head` と `first_pos` を決めます。

```text
head      = (count >= 上限) ? ((newest_phys + 1) % 上限) : count      <- 満杯なら最新の次が最古
first_pos = (unsent_phys + count - ((count >= 上限) ? head : 0)) % count   <- 物理から論理へ
            (pending > 0 のときだけ)
```

既定の 100000 件では、16 バイトの読み出しを 100000 回行うので、数秒かかります。

## backlog_append

```text
マウントしていない                   -> -ENODEV
時刻が 0 未満, または UINT32_MAX より大きい -> -EINVAL
open(CREATE | RDWR)
満杯なら上書きされる記録 (head の位置) を読んで未送信かを調べる
          (読めない記録と CRC が合わない記録は送信済みとして扱う)
encode() -> head の位置に write_record() -> close
状態を更新
```

状態を更新するのは、書き込みと close の両方が成功してからです。

| 場合 | 更新 |
|:---|:---|
| 満杯 | `head = (head + 1) % 上限`。上書きした記録が未送信なら `pending--`。`first_pos` を 1 減らす (0 まで) |
| 満杯でない | `count++`。`head = (count >= 上限) ? 0 : count` |
| 未送信で保存 | `pending` が 0 だったら `first_pos = count - 1`。そのあと `pending++` |

書き込みでは、`fs_seek()` のあと、16 バイトを `fs_write()` で 1 回で書きます。途中で電源が切れて書きかけになると、CRC が合わなくなるので、読み飛ばされます。

## backlog_read

未送信の記録のうち、`index` 番目 (0 が最も古い) を読みます。

1. `index >= pending` なら、`-EINVAL` を返します。
2. 論理の位置 `first_pos` から順に、1 件ずつ読みます。
3. CRC が合う未送信の記録だけを数えます。`index` 番目が見つかったら、それを返します。
4. 最後まで見つからなければ、`-ENOENT` を返します (ファイルが壊れていて、`pending` の数と合わない)。

`first_pos` から読み始めるので、それより前の送信済みの記録は調べずに済みます。`direct.c` は `index` に `queued` (3 以下) を渡すので、探す範囲は狭くなります。

## backlog_commit

古い方から `n` 件の未送信の記録を、送信済みにします (フラグの 1 バイトだけを書き換える)。

1. `n > pending` なら `-EINVAL` を返します。`n == 0` なら、何もせずに成功を返します。
2. `first_pos` から順に記録を読みます。CRC が合う未送信の記録なら、`mark_sent()` でフラグを書いて、`marked++`、`pending--` とします。`first_pos` は、送信済みの記録や壊れた記録を飛ばしながら、1 つずつ進めます。
3. `n` 件を書き終えるか、最後まで読むと終わります。
4. 書き込みに失敗したら、`LOG_ERR` を出して、そのエラーを返します (それまでに書いた分は反映されています)。
5. `n` 件に足りなかったときは、記録が壊れているとみなして、`pending` を足りない分だけ減らし (数を実際のファイルに合わせる)、`-EIO` を返します。

フラグは CRC の対象外なので、フラグを書き換えても、記録の整合性は保たれます。

## backlog_foreach_since

指定の時刻 (UNIX 時刻 [s]) 以降の記録を、送信済みの記録も含めて、古い順に関数に渡します。グラフの履歴の復元 (`history_store.c`) が使います。

1. 記録の時刻は、論理の位置の順に増えているとみなします。二分探索で、時刻が `since` 以上になる最初の論理の位置を探します。
2. 壊れた記録に当たったときは、「新しい」ものとして扱い、探す範囲を前に寄せます。こうすると、余分な記録を渡すことはあっても、誤って落とすことはありません。
3. その位置から最後まで 1 件ずつ読み、CRC が合う記録だけを `visit(rec, ctx)` に渡します。

二分探索は、時刻が単調に増えることを前提にしています。RTC の時刻を大きく戻すと (たとえば、ゲートウェイがずれた時刻を書き込むと)、順序が崩れて、探した位置がずれます。

## 補助の関数

| 関数 | 役割 |
|:---|:---|
| `physical()` | 論理の位置から、物理の位置を求める |
| `read_slot()` | 物理の位置へ `fs_seek()` して、16 バイト読む。短ければ `-EIO` |
| `write_record()` | 物理の位置へ `fs_seek()` して、16 バイト書く。短ければ `-EIO` |
| `mark_sent()` | `物理の位置 × 16 + 8` へ `fs_seek()` して、`1` を 1 バイト書く |
| `decode()`、`encode()` | 16 バイトと `struct backlog_record` の相互変換。`decode()` は CRC を確かめる |
| `record_crc()` | 記録の CRC-32 (0 から 7 バイト目と、気圧があれば気圧の 2 バイト) |
| `open_file()` | `fs_open()`。失敗したら `LOG_ERR` を出す |

## エラーの一覧

| 値 | 関数 | 意味 |
|:---|:---|:---|
| `-ENODEV` | init、append、foreach_since | マウントできない、またはマウントしていない |
| `-EINVAL` | append | 時刻が範囲の外 (0 から UINT32_MAX) |
| `-EINVAL` | read、commit | `index` や `n` が大きすぎる |
| `-ENOENT` | read | 未送信の記録が見つからない (ファイルが壊れている) |
| `-EIO` | read_slot など | 読み書きが短い |
| `-EIO` | commit | 送信済みにする記録が足りない |
| そのほか負の errno | 全て | `fs_*` の失敗 |

## 注意点

- 追記のたびに、ファイルを開いて閉じます。そのため 5 秒ごとに FAT の更新が起きますが、閉じるたびに書き込みが確定するので、電源が切れても直前の記録まで残ります。
- 16 バイトの記録は、SD カードのセクタ (512 バイト) の中に収まります。フラグの書き換えは 1 バイトだけですが、FAT ではセクタ単位で書き直されます。
- 上限 (`CONFIG_THERMO_BACKLOG_MAX_RECORDS`) を小さくして再ビルドしても、ファイルには新しい上限より多くの記録が残っています。`backlog_init()` は先頭から上限の件数までしか読まないので、それより後ろの記録は無視されます。
- 時刻 (`unix_s`) は `int64_t` ですが、32 ビットで保存するので、保存できるのは 2106 年 (UINT32_MAX) までです。RTC のドライバが扱うのは 2099 年までなので、問題ありません。
- 排他制御はありません。呼ぶのは、メインスレッド (`direct.c`) と、シェルのスレッド (`thermo sd` の `backlog_init()`) です。`direct_sd_check()` が `backlog_init()` を呼ぶのは、マウントできていないとき (`is_backlog_ready` が false で、`direct_sample()` が `backlog_*()` を呼ばないとき) だけなので、保存の途中とは重なりません。
