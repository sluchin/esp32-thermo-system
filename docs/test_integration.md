# 結合試験項目書 (thermo-node の SD カードの記録と送信)

thermo-node の SD カードへの保存 (送信済みフラグつき)、あとからの送信、グラフの復元を、実機で確かめる試験項目です。対象は、単体テスト (`docker compose run --rm test-node`) では確かめられない、SD カード、BLE、WiFi、AWS IoT Core との結合です。

記録の形式と読み方は、[sd_log.md](sd_log.md) を見てください。

## 1. 試験の対象と前提

### 対象の機能

| 機能 | 内容 |
|:---|:---|
| 保存 | 全ての測定値 (5 秒ごと) を、送信済みフラグつきで SD カードに保存する |
| 送信 | BLE も WiFi も使えなかった間の記録を、つながったときに、測った時刻のまま古い順に送る |
| 上限 | 上限の件数 (`THERMO_BACKLOG_MAX_RECORDS`) に達したら、古い記録から上書きする |
| グラフ | 起動のときに、OLED のグラフ (約 6 時間) を SD カードの記録から戻す。測定値のない区間には、線を引かない |

### 試験の環境

| 項目 | 内容 |
|:---|:---|
| ノード | XIAO ESP32C3、拡張ボード (OLED、RTC、SD カードスロット、ユーザボタン、ブザー)、センサ (AHT20 と BMP280、または DHT11) |
| ゲートウェイ | thermo-gateway を書き込んだ XIAO ESP32C3 (WiFi で AWS IoT Core につなぐ) |
| SD カード | FAT32 でフォーマットした SD カード (例: 2 GB) |
| WiFi | 2.4 GHz のアクセスポイント (電源を切って、つながらない状態にできること) |
| AWS | AWS IoT Core のテストクライアントで、トピックの受信を見られること ([aws_setup.md](aws_setup.md)) |
| PC | シリアル (`picocom -b 115200 /dev/ttyACM0`)、SD カードリーダー、Python 3 ([sd_log.md](sd_log.md) の読み取りスクリプト) |

### 事前の準備

1. この版のファームウェアを、ノードに書き込む (`docker compose run --rm build-node`、`scripts/flash.sh node`)。
2. シェルの `thermo set` で、設定 (SSID、パスワード、エンドポイント、クライアント ID、証明書) を入れる ([setup.md](setup.md)。確認は `thermo show`)。
3. 上限の試験 (IT-401〜IT-405) には、上限を小さくしたビルドを使う (例: `-DCONFIG_THERMO_BACKLOG_MAX_RECORDS=100`)。ほかの試験には、既定のビルドを使う。
4. 指定のない限り、試験のたびに SD カードを空にする (PC で消すか、`fs rm /SD:/backlog.bin` を実行する)。

### 記号

- 結果の欄: **OK** (期待どおり)、**NG** (期待と違う。内容を備考に書く)、**-** (未実施)。
- 実施日と実施者は、各表の下の欄に書く。
- 「済」は、これまでの調整で実機で確かめた項目です (2026-10-12)。正式な試験では、もう一度実施する。

## 10. 既知の制約 (試験の対象外と、結果の見方)

- 送信済みかどうかは、publish の成功で決め、PUBACK は待ちません。接続が切れる直前に送った記録は、AWS に届かないことがあります (`TODO.md`)。
- ゲートウェイにつながっている間の記録は、ゲートウェイが送るものとして、送信済みにします。そのため、ゲートウェイがインターネットにつながっていない間の分は、AWS に届きません。
- 起動のときに、ファイル全体を読みます。既定の 100000 件では、起動に数秒かかります。
- 測定のたびに SD カードに書くので、書き込みの回数が増えます (1 日に約 17000 回の、1 件ずつの追記)。
- まだ全ての項目を、実機で試験してはいません。「済」の項目は、IT-101、IT-106、IT-201〜IT-203、IT-205、IT-801、IT-802、IT-804 です (2026-10-12)。
